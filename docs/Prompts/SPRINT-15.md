## Architecture Context

**The problem:** When a TeraSwap user signs a swap on Ledger (or any hardware wallet), they see raw hex — a string of opaque bytes. This is "blind signing." Users have no way to verify what they're actually approving. Blind signing has contributed to billions in ecosystem losses.

**The solution:** ERC-7730 defines a JSON metadata file that maps smart contract calldata to human-readable fields. When registered, Ledger's Secure Screen (and progressively MetaMask, Trezor, WalletConnect) shows:
- "Swap 1,500 USDC → ETH via 1inch"
- "Minimum output: 0.42 ETH"
- "Router: 0x1111... (1inch v6)"

Instead of: "0x7c025200000000000000000000000000..."

**What's new since our backlog entry:** The Ethereum Foundation officially launched the clear signing initiative (May 12, 2026, 217K views). The ecosystem now includes ERC-7730 (descriptor standard), a neutral mirrorable registry, ERC-8176 (attestation framework for auditors), and open developer tooling. Contributors: Ledger, Trezor, MetaMask, WalletConnect, Cyfrin, Fireblocks, Zama, Sourcify. This is no longer Ledger-only — it's becoming the Ethereum-wide standard.

**FeeCollector V2 functions to describe:**
1. `swapTokenWithFee(address token, uint256 totalAmount, address router, bytes routerData, address tokenOut, uint256 minimumOutput)` — ERC-20 input swap
2. `swapETHWithFee(address router, bytes routerData, address tokenOut, uint256 minimumOutput)` — ETH input swap (amount from msg.value)

**Objective:** Exclude the `fv/` directory from Foundry compilation so contract tests pass in CI.

## Prompt 105 — ERC-7730 descriptor JSON for FeeCollector V2

**Status:** Pending

**Context:** FeeCollector V2 at `0x47f24068932Ac49bcbeD3aD105af57C6ECDF7459` has two user-facing functions: `swapTokenWithFee` and `swapETHWithFee`. Both need ERC-7730 descriptors so hardware wallets can display human-readable transaction details.

**Objective:** Create the ERC-7730 JSON descriptor file for FeeCollector V2.

**Requirements:**

1. **Create `contracts/clear-signing/erc7730-feecollector-v2.json`** following the ERC-7730 schema:

   ```json
   {
     "$schema": "https://eips.ethereum.org/assets/eip-7730/erc7730-v1.schema.json",
     "context": {
       "contract": {
         "deployments": [
           {
             "chainId": 1,
             "address": "0x47f24068932Ac49bcbeD3aD105af57C6ECDF7459"
           }
         ],
         "abi": [/* relevant function signatures */]
       }
     },
     "display": {
       "formats": {
         "swapTokenWithFee": {
           "intent": "Swap tokens via TeraSwap",
           "fields": [
             { "path": "token", "label": "Input Token", "format": "addressName" },
             { "path": "totalAmount", "label": "Amount", "format": "tokenAmount", "params": { "tokenPath": "token" } },
             { "path": "tokenOut", "label": "Output Token", "format": "addressName" },
             { "path": "minimumOutput", "label": "Minimum Output", "format": "tokenAmount", "params": { "tokenPath": "tokenOut" } },
             { "path": "router", "label": "Router", "format": "addressName" }
           ],
           "excluded": ["routerData"]
         },
         "swapETHWithFee": {
           "intent": "Swap ETH via TeraSwap",
           "fields": [
             { "path": "@.value", "label": "ETH Amount", "format": "tokenAmount", "params": { "nativeCurrency": true } },
             { "path": "tokenOut", "label": "Output Token", "format": "addressName" },
             { "path": "minimumOutput", "label": "Minimum Output", "format": "tokenAmount", "params": { "tokenPath": "tokenOut" } },
             { "path": "router", "label": "Router", "format": "addressName" }
           ],
           "excluded": ["routerData"]
         }
       }
     }
   }
   ```
   
   NOTE: The above is a structural guide. The Code Agent MUST check the latest ERC-7730 schema at https://eips.ethereum.org/EIPS/eip-7730 and the builder at https://www.clearsign.app/builder for the exact field format, required properties, and any v1.1+ changes since this prompt was written. The schema may have evolved.

2. **Include the minimal ABI** — only the two function signatures, not the full contract ABI. The descriptor only needs the functions it describes.

3. **Exclude `routerData`** — this is opaque bytes (encoded swap calldata for the underlying DEX). It cannot be meaningfully displayed to users and should be explicitly excluded per the ERC-7730 `excluded` field.

4. **Verify against the FeeCollector V2 ABI:**
   - Read the contract ABI from `contracts/FeeCollector.sol` or the deployment artifacts
   - Ensure selector bytes match the function signatures
   - Ensure parameter names and types match exactly

**Do NOT**

- Include admin functions (`setFee`, `withdrawFees`, etc.) — only user-facing swap functions
- Include the full contract ABI — only the 2 swap functions
- Guess the ERC-7730 schema — validate against the official schema
- Deploy or submit anything — that's P106

**Files affected**

- `contracts/clear-signing/erc7730-feecollector-v2.json` (new)

**Expected output**

- 1 atomic commit
- Valid ERC-7730 JSON descriptor
- Covers both `swapTokenWithFee` and `swapETHWithFee`
